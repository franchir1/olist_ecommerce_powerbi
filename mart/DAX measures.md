# DAX Measures Documentation

The model uses a single shared calendar dimension (`analysis_dim_date`).
The default time reference is purchase date.
Delivery-based KPIs explicitly activate the delivery relationship using `USERELATIONSHIP`.
All measures respect their originating fact grain.

---

## Basic Metrics

### BASIC – Total Customers

```DAX
BASIC – Total Customers = 
DISTINCTCOUNT ( analysis_dim_customer[customer_unique_id] )
```

Meaning
Number of unique customers in the model.

Logic
Counts `customer_unique_id`, representing a real individual.
Calculated directly on the customer dimension to avoid order-level duplication.

Model dependency
Requires a consistent customer bridge between dimension and order fact.

Interpretation
Measures customer base size within the current filter context (typically purchase date).

---

### BASIC – Total Orders

```DAX
BASIC – Total Orders = 
DISTINCTCOUNT ( analysis_fact_orders[order_id] )
```

Meaning
Total number of orders.

Logic
The orders fact is modeled at order grain; `order_id` is unique.

Interpretation
Represents transaction volume under the current filter context.

## Revenue Metrics

### KPI – Total Revenue

```DAX
KPI – Total Revenue =
CALCULATE(
    SUM ( analysis_fact_order_items[price] ),
    analysis_fact_orders[order_status] = "delivered",
    USERELATIONSHIP(
        analysis_fact_orders[order_purchase_date_key],
        analysis_dim_date[date_key]
    )
)
```

Meaning
Revenue generated by delivered orders, attributed to purchase date.

Logic
Revenue is calculated at item grain.
Only orders with `order_status = "delivered"` are included.
Explicitly enforces purchase-date context.

Interpretation
Measures realized revenue aligned to the commercial event (purchase), not the logistics event.

---

### KPI – Average Order Value

```DAX
KPI – Average Order Value = 
DIVIDE ( [KPI – Total Revenue], [KPI – Delivered Orders (Delivery Date)] )
```

Meaning
Average revenue per delivered order.

Logic
Revenue numerator filtered to delivered orders.
Denominator aligned to delivered-order count.

Consideration
Revenue is attributed to purchase date, while the denominator may reflect delivery-date context depending on report slicing. Temporal alignment must be verified in visuals.

## Delivery Performance Metrics

### KPI – Delivered Orders (Delivery Date)

```DAX
KPI – Delivered Orders (Delivery Date) = 
CALCULATE(
    DISTINCTCOUNT(analysis_fact_orders[order_id]),
    analysis_fact_orders[order_status] = "delivered",
    USERELATIONSHIP(
        analysis_fact_orders[order_delivered_date_key],
        analysis_dim_date[date_key]
    )
)
```

Meaning
Number of delivered orders attributed to delivery date.

Logic
Filters on delivered status.
Activates delivery-date relationship.

Interpretation
Represents operational throughput of completed deliveries.

---

### KPI – Avg Delivery Delay (Days)

```DAX
KPI – Avg Delivery Delay (Days) = 
VAR DeliveredOrders =
    FILTER (
        analysis_fact_orders,
        NOT ISBLANK ( analysis_fact_orders[order_delivered_date] )
            && NOT ISBLANK ( analysis_fact_orders[order_estimated_delivery_date] )
    )
RETURN
CALCULATE(
AVERAGEX (
    DeliveredOrders,
    DATEDIFF (
        analysis_fact_orders[order_estimated_delivery_date],
        analysis_fact_orders[order_delivered_date],
        DAY
    )
),
USERELATIONSHIP(
            analysis_fact_orders[order_delivered_date_key],
            analysis_dim_date[date_key]
        )
)
```

Meaning
Average difference between estimated and actual delivery date.

Logic
Includes only orders with both dates available.
Positive values indicate late deliveries; negative values indicate early deliveries.
Evaluated strictly in delivery-date context.

Interpretation
Measures central tendency of delivery accuracy.

---

### KPI – P98 Delivery Delay (Days)

```DAX
KPI – P98 Delivery Delay (Days) = 
VAR DeliveredOrders =
    FILTER(
        analysis_fact_orders,
        NOT ISBLANK(analysis_fact_orders[order_delivered_date]) &&
        NOT ISBLANK(analysis_fact_orders[order_estimated_delivery_date])
    )
RETURN
PERCENTILEX.INC(
    DeliveredOrders,
    DATEDIFF(
        analysis_fact_orders[order_estimated_delivery_date],
        analysis_fact_orders[order_delivered_date],
        DAY
    ),
    0.98
)
```

Meaning
98th percentile of delivery delay distribution.

Logic
Captures extreme late-delivery behavior.
Not relationship-activated; depends on current context.

Interpretation
Highlights tail risk in logistics performance. More robust for SLA monitoring than mean delay.

---

### KPI – Late Delivery Rate

```DAX
KPI – Late Delivery Rate = 
VAR LateOrders =
    COUNTROWS (
        FILTER (
            analysis_fact_orders,
            NOT ISBLANK ( analysis_fact_orders[order_delivered_date] )
                && NOT ISBLANK ( analysis_fact_orders[order_estimated_delivery_date] )
                && analysis_fact_orders[order_delivered_date]
                    > analysis_fact_orders[order_estimated_delivery_date]
        )
    )
RETURN
    CALCULATE(
        DIVIDE ( LateOrders, [KPI – Delivered Orders (Delivery Date)] ),
        USERELATIONSHIP(
            analysis_fact_orders[order_delivered_date_key],
            analysis_dim_date[date_key]
        )
    )
```

Meaning
Share of delivered orders arriving after estimated date.

Logic
Counts orders where actual delivery exceeds estimate.
Denominator aligned to delivered orders under delivery-date context.

Consideration
Numerator is computed prior to relationship activation; semantic alignment assumes consistent filter propagation.

## Logistics Cost Metrics

### KPI – Avg Order Weight (Kg)

```DAX
KPI – Avg Order Weight (Kg) = 
CALCULATE(
    DIVIDE(
    SUMX(
        analysis_fact_order_items,
        RELATED(analysis_dim_products[product_weight_g])
    ) / 1000,
    [BASIC – Total Orders]
),
USERELATIONSHIP(
    analysis_fact_order_items[order_delivered_date_key],
    analysis_dim_date[date_key]
))
```

Meaning
Average order weight in kilograms.

Logic
Aggregates item-level product weight via relationship to product dimension.
Converts grams to kilograms.
Divides total delivered weight by total orders.
Evaluated under delivery-date context.

Interpretation
Measures shipment mass intensity per order.

---

### KPI – Freight Costs per Kg Delivered

```DAX
KPI Freight costs per Kg delivered = 
DIVIDE(
    SUM(analysis_fact_order_items[freight_value]),
    SUMX(
        analysis_fact_order_items,
        RELATED(analysis_dim_products[product_weight_g]) / 1000
    )
)
```

Meaning
Freight cost per kilogram shipped.

Logic
Numerator: total freight charges at item grain.
Denominator: total shipped weight in kilograms.

Interpretation
Captures logistics cost efficiency normalized by physical volume.

## Customer Metrics

### KPI – Fidelity Customer Rate

```DAX
KPI – Fidelity Customer Rate = 
VAR RepeatCustomers =
    COUNTROWS (
        FILTER (
            VALUES ( analysis_dim_customer[customer_unique_id] ),
            [BASIC – Total Orders] > 1
        )
    )
RETURN
DIVIDE ( RepeatCustomers, [BASIC – Total Customers] )
```

Meaning
Share of customers placing more than one order.

Logic
Evaluated at customer grain.
Depends on purchase-date context.

Interpretation
Measures customer retention within the selected period.

## Review Metrics

### KPI – Average Review Score

```DAX
KPI – Average Review Score = 
AVERAGE ( analysis_fact_reviews[review_score] )
```

Meaning
Average rating assigned by customers.

Logic
Simple mean of review scores at review grain.

Interpretation
Measures perceived satisfaction level.

---

### KPI – Orders with Feedbacks

```DAX
KPI – Orders with Feedbacks = 
DIVIDE(
        DISTINCTCOUNT(analysis_fact_reviews[order_id]),
        DISTINCTCOUNT(analysis_fact_orders[order_id])
    )
```

Meaning
Share of orders receiving at least one review.

Logic
Numerator: distinct orders appearing in reviews.
Denominator: distinct orders overall.

Interpretation
Measures engagement rate in post-purchase feedback.

---

### KPI – Avg Review Response Time (Days)

```DAX
KPI – Avg Review Response Time (Days) = 
VAR AnsweredReviews =
    FILTER(
        analysis_fact_reviews,
        NOT ISBLANK(analysis_fact_reviews[review_answer_date])
            && NOT ISBLANK(analysis_fact_reviews[review_creation_date])
    )
RETURN
AVERAGEX(
    AnsweredReviews,
    DATEDIFF(
        analysis_fact_reviews[review_creation_date],
        analysis_fact_reviews[review_answer_date],
        DAY
    )
)
```

Meaning
Average time between review creation and seller response.

Logic
Includes only answered reviews.
Calculated at review grain.

Interpretation
Measures responsiveness of sellers to customer feedback.

---

### KPI – Review Response Coverage

```DAX
KPI – Review Response Coverage = 
DIVIDE(
    CALCULATE(
        DISTINCTCOUNT(analysis_fact_reviews[review_id]),
        NOT ISBLANK(analysis_fact_reviews[review_answer_date])
    ),
    DISTINCTCOUNT(analysis_fact_reviews[review_id])
)
```

Meaning
Share of reviews that received a seller response.

Logic
Numerator: reviews with non-null answer date.
Denominator: total reviews.

Interpretation
Measures customer service coverage on feedback handling.

---

## Design Summary

All measures respect their originating fact grain (order, item, or review).
Revenue and customer metrics align with purchase event semantics.
Delivery metrics explicitly activate delivery-date relationship.
Logistics metrics normalize cost and weight for structural comparability.
Review metrics operate at review grain and measure both satisfaction and operational responsiveness.

The model maintains semantic separation between commercial event (purchase), operational event (delivery), and feedback event (review), enabling multi-event analytical consistency under a single shared calendar dimension.
